# Executive summary

**Object:** MAX for Android, package `ru.oneme.app`, installed RuStore-channel build `26.35.1 (6867)`, collected 11 October 2026 from a Pixel 8 Pro running Android 17. The APK identities and signer are recorded in the [public build manifest](../evidence/2026-10-11/build.json).

**Assessment:** The completed work found **no confirmed exploitable vulnerability**. The APK declares sensitive permissions, exports entry points, and explicitly allows cleartext traffic to eight named domains. These observations warrant targeted follow-up, but do not demonstrate misuse or traffic to those domains. [Static evidence](../evidence/2026-10-11/static-summary.json) records the exact declarations and DEX string indicators.

**Selected code results:** DEX checks show that the MyTracker installed-package provider setter is a no-op in this build, while another method still queries installed packages. DiskUsageWorker selects app-related roots and conditionally schedules a sample report above 10 GiB. A fixed `logcat` command is present. These results narrow earlier claims without proving whether the relevant paths run on this account. [Bytecode excerpts](../evidence/2026-10-11/bytecode-excerpts.md).

**Correction:** Earlier repository drafts described the app as spyware and asserted bulk application inventory uploads, whole-device file scanning and remote command execution. The excerpts supplied in those drafts did not prove those behaviors. The current build's manifest also does not declare `SYSTEM_ALERT_WINDOW`, contrary to a prominent claim in the earlier report. The [claim register](../docs/CLAIM_REGISTER.md) explains each correction.

**Runtime result:** An isolated Android 17 emulator using the identical APK set completed startup and background observations before and after authentication. Refusal and revocation of camera and visual-media access produced the expected permission-denied UI; all affected grants, flags and AppOps modes were restored. Microphone refusal produced a system prompt and returned to an empty composer after denial. Active-recording revocation was not run. Guest-wide captures provided bounded metadata; the parser found no HTTP request signatures, and TLS contents remain unknown. [Authenticated results](../evidence/2026-10-11/runtime-authenticated.json), [microphone result](../evidence/2026-10-11/runtime-microphone.json), [minimal UI evidence](../evidence/2026-10-11/runtime-ui-excerpts.json).

**Account boundary:** The user supplied an account designated for testing that contained pre-existing conversations. A separately authorized single text-message send was visually checked; recipient details, message content and chat screenshots are excluded from public evidence and security findings. No audio, image or contact submission was performed by the tests.

**Limits:** The personal-device phase acquired the installed APK set and read permission state. It did not inspect private app data, open personal conversations, change permissions, intercept TLS, send messages, or execute risky feature flows. Accordingly, the report cannot conclude that sensitive data is or is not transmitted. Only the examined RuStore-channel APK set and the documented personal-device and isolated-emulator environments are in scope. A public RuStore listing displayed `26.35.0` on 11 October 2026; the installed package reported `26.35.1`. Store update availability was not verified inside RuStore.
